# Example programs

Each `.asm` program is assembled to `.hex` and simulated with `cpu_tb.v`, except `pmod.asm` (an endless hardware demo tested by `tb/top_pmod_tb.v`). If a `.ref` file exists, the testbench compares the whole sequence of bytes written to `OUT`, in order, with the contents of that file, and also checks that the number of outputs is the expected one.

## How to run a program

```bash
cd cpu8
make sim PROG=programs/countdown
make wave PROG=programs/countdown  # Opens GTKWave
```

## Program descriptions

| Program | Purpose | What it checks |
|---|---|---|
| `callret.asm` | Calls/subroutines with `CALL`/`RET` | Correct return flow after a subroutine. |
| `countdown.asm` | Countdown loop | Conditional/unconditional branches, loops. |
| `extensions.asm` | ISA extensions (Phase 8) | Immediates `ADDI`/`SUBI`/`CMPI`, indexed `LD/ST [rs+off]` (incl. negative offset) and signed (`JLT/JGE/JLE/JGT`) and status (`JVS/JVC/JMI/JPL`) branches. |
| `extensions3.asm` | Extended instructions behind the `0xFA` prefix (Phase 12) | `NEG`, `NOT`, `ADC`, `SBC`, `SWAP`/`XCHG`, `ROL`, `ROR` and 16-bit `LDW`/`STW`, including the carry/borrow and the address bit 8 going to `C`. |
| `extensions4.asm` | Rest of the `0xFA` prefix (Phase 12) | Flags-only `TEST`, `PUSHF`/`POPF` (flags byte on the stack) and the 16-bit pair ops `ADCW`/`SUBW` over `A:B` and `C:D`, including the carry/borrow chain and the 16-bit `Z`. |
| `fase4.asm` | Historical development program | Consolidated basic functional path. |
| `fibonacci.asm` | Generates a Fibonacci sequence | Arithmetic, loops, registers. |
| `incdec.asm` | `INC`/`DEC` on registers | Flags `Z,N` (INC/DEC do **not** modify `C`). |
| `indirect.asm` | Indirect addressing `[rs]` | Register-indirect load/store. |
| `irq.asm` | Hardware interrupt | IRQ handling with `IRQ_VECTOR=0x10`. Verifies it is handled **once**; the handler returns with `RETI`, which restores `C,Z,N,V`. |
| `logic.asm` | Bitwise and shift instructions | `OR`/`XOR` (Z/N from the result), `SHL`/`SHR` (the displaced bit goes to `C`) and `ROL`/`ROR` rotating **through** `C`, including the round trip `0x40 -> 0x81 -> 0x40`. |
| `multiply.asm` | Multiplication by repeated addition | Algorithm with loops and an accumulator. |
| `muldiv.asm` | Hardware `MUL`/`DIV` (Phase 9) | Multiplication, overflow (`C=1`), division and division by zero (`C=1`). |
| `inout.asm` | `IN` input and port output `OUT n, rd` (Phase 9) | Reads the input port and writes to ports 0/1/2. |
| `pmod.asm` | iCEstick Pmod input demo | Endless `IN A; OUT A; JMP` loop: the low five bits of the Pmod byte appear on the LEDs. It never halts, so it is excluded from the halt-based harness and tested by `tb/top_pmod_tb.v`; `make fpga FPGA_PROG=pmod` builds its bitstream. |
| `euclid.asm` | Greatest common divisor (Euclid's algorithm) | GCD of (144,60) as the remainder `a − (a/b)·b` using hardware `DIV`/`MUL`. |
| `factorial.asm` | Iterative factorial (5! = 120) | Loop with `MUL` and `DEC`; stops when `B` reaches 0. |
| `primes.asm` | Primes below 32 (trial division) | Nested loops + RAM cells; uses `DIV`/`MUL` for the remainder. |
| `sort.asm` | Sorts an array with bubble sort | `.db` directive for the data and indexed `[B+off]`; sorts in place. |
| `stack.asm` | `PUSH`/`POP` + `RET` operations | Correct stack use and address recovery. |
| `reserved.asm` | Reserved encodings are no-ops | Executes reserved opcodes (`0xE2`, `0xFA 0xF0`) and `DI`, showing that they decode as backward-compatible no-ops and covering the decoder's defensive `default:` branches. |

## Associated files

- `.asm` – Assembler source code
- `.hex` – Machine code generated by `asm/assembler.py`
- `.ref` – Expected `OUT` byte sequence: the values written to `OUT` during the simulation, in order, one per line (hex bytes)

## Assembling everything manually

```bash
for f in programs/*.asm; do
  python3 asm/assembler.py "$f" -o "${f%.asm}.hex"
done
```

## Notes

- `cpu_tb.v` stops the simulation when it reaches `HLT` or after a reasonable number of cycles.
- `pmod.asm` is the exception: it loops forever on purpose, so `cpu_tb.v`, the
  program regression and the differential fuzzer skip it. `tb/top_pmod_tb.v`
  loads its `.hex` and checks several Pmod values against the top-level LEDs.
- Every byte written to `OUT` during the simulation is compared, in order, with its line in `.ref` (one byte per line); the testbench also fails if the number of outputs differs, so a missing or an extra byte is an error.

A normal example only needs its `.asm` (and `.ref`); the endless `pmod.asm` demo
is the exception and is wired into the module test and FPGA targets.
